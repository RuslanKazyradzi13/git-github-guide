# Как помочь проекту

Спасибо, что хотите сделать методичку лучше! Помочь можно, даже если вы только начинаете: свежий взгляд новичка лучше всего находит непонятные места.

Участвуя в проекте, вы соглашаетесь соблюдать [кодекс поведения](CODE_OF_CONDUCT.md).

## Сообщить об ошибке или предложить идею

[Создайте Issue](https://github.com/RuslanKazyradzi13/git-github-guide/issues/new/choose) по одной из форм:

| Форма | Когда выбирать |
| --- | --- |
| Ошибка в тексте | Опечатка, неточность, команда не работает или выводит другое |
| Устаревшие сведения | Вышла новая версия Git, изменился интерфейс GitHub, ссылка ведёт не туда |
| Предложение | Новая тема, пример, схема или улучшение структуры |
| Вопрос по материалу | Что-то непонятно, даже после повторного чтения |

Перед созданием поищите похожий Issue — возможно, об этом уже написали.

> [!IMPORTANT]
> Уязвимости в скриптах `tools/` и в учебном проекте `examples/tempconv/` не публикуйте в Issue. Сообщите о них закрыто — см. [SECURITY.md](SECURITY.md).

## Предложить исправление

Порядок тот же, что в [главе 5](05_vetki_i_pull_requests.md): форк, ветка, Pull Request.

1. Сделайте форк репозитория и клонируйте его:

   ```powershell
   git clone https://github.com/<логин>/git-github-guide.git
   cd git-github-guide
   ```

2. Создайте ветку для правки:

   ```powershell
   git switch -c fix/glava-6-restore
   ```

3. Внесите изменения по правилам ниже.
4. Обновите оглавления и схемы, проверьте ссылки (нужен Python 3.11+):

   ```powershell
   python tools/toc.py
   python tools/make_images.py
   python tools/check_links.py
   ```

   Последняя команда должна завершиться без строк `ОШИБКА`.
5. Добавьте запись в раздел `[Unreleased]` файла [CHANGELOG.md](CHANGELOG.md).
6. Сделайте коммит, отправьте ветку и откройте Pull Request. Заполните шаблон описания.

После открытия Pull Request автоматически запустятся те же проверки. PDF пересобирать не нужно: сопровождающий обновляет его при выпуске версии.

### Сообщения коммитов

Формат — [Conventional Commits](https://www.conventionalcommits.org/ru/v1.0.0/), описание по-русски, в повелительном наклонении:

```text
docs: исправить пример git restore в главе 6
docs(glossary): добавить термин «тег»
fix(tools): учитывать якоря с цифрами в check_links.py
ci: обновить actions/checkout
```

| Тип | Что меняется |
| --- | --- |
| `docs` | Текст глав, словарь, источники, шаблоны, схемы |
| `fix` | Ошибка в скриптах `tools/` или в коде учебного проекта |
| `feat` | Новая возможность скриптов или учебного проекта |
| `ci` | Автоматические проверки в `.github/` |
| `chore` | Служебные файлы, которые не попадают к читателю |

## Правила текста

- **Пишите для человека без опыта.** Короткие предложения, обращение на «вы», один шаг — одно действие. Новое понятие сначала объясните, потом используйте.
- **Термины — как в [словаре](glossary.md).** Если вводите новый термин, добавьте его в словарь.
- **Команды — для PowerShell в Windows 10 и 11.** Ввод — в блоке `powershell`, вывод — в блоке `text`. Приглашение `PS C:\...>` не пишите.
- **Вывод команд — только настоящий.** Выполните команду и скопируйте результат из терминала. Не сочиняйте вывод по памяти.
- **Факты — по официальным источникам.** Версии, названия кнопок, ограничения и сроки сверяйте с документацией. Источник добавьте в [sources.md](sources.md), дату проверки обновите.
- **Предупреждайте об опасном.** Команды, которые удаляют изменения или переписывают историю, помечайте знаком ⚠ и блоком `[!WARNING]` или `[!CAUTION]`.
- **Не выдавайте схемы за снимки экрана.** Схемы интерфейса GitHub помечены надписью «Схема интерфейса · не скриншот».
- **Не подставляйте вымышленные данные.** В шаблонах — только заполнители в `[КВАДРАТНЫХ СКОБКАХ]`.
- **Юридические сведения — образовательные.** Не формулируйте их как консультацию юриста.
- **Оформление — минималистичное.** Без лишних эмодзи, жирного шрифта и украшений.

## Схемы и анимация

- SVG-схемы в `images/` создаёт скрипт `tools/make_images.py`. Чтобы изменить схему, правьте скрипт и запускайте его заново — не редактируйте SVG вручную.
- Анимацию в шапке README и картинку для соцсетей создаёт `node tools/make_hero.mjs` из `tools/hero.html`.

Подробнее об инструментах — в [tools/README.md](tools/README.md).

## Версии

Методичка нумеруется по [Semantic Versioning](https://semver.org/lang/ru/) в таком смысле:

| Часть номера | Когда увеличивается | Пример |
| --- | --- | --- |
| MAJOR | Меняется структура: главы переименованы или перенумерованы, старые ссылки на разделы перестают работать | `1.4.2` → `2.0.0` |
| MINOR | Добавлены главы, разделы, шаблоны или схемы | `1.4.2` → `1.5.0` |
| PATCH | Исправлены ошибки и опечатки, обновлены версии программ и ссылки | `1.4.2` → `1.4.3` |

При выпуске версии сопровождающий переносит записи из `[Unreleased]` в новый раздел [CHANGELOG.md](CHANGELOG.md), пересобирает PDF, ставит тег `vX.Y.Z` и публикует релиз с PDF-файлом.

## Поддержка актуальности

- Перед выпуском версии запустите полную проверку ссылок, включая внешние: `python tools/check_links.py --web`.
- Раз в полгода сверяйте версии в [sources.md](sources.md) с официальными сайтами: Git, Git для Windows, действия GitHub Actions, Python.
- Интерфейс GitHub меняется. Если описание расходится с сайтом, ориентируйтесь на документацию GitHub и создайте Issue «Устаревшие сведения».

## Лицензия вклада

Отправляя Pull Request, вы соглашаетесь, что ваш вклад распространяется на тех же условиях, что и проект: тексты, схемы и шаблоны — [CC BY 4.0](LICENSE), код в `tools/` и `examples/` — [MIT](LICENSE-CODE).
