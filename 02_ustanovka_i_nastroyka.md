# Глава 2. Установка и первая настройка

В этой главе вы научитесь пользоваться терминалом, установите Git на Windows и представитесь ему: укажете имя и почту. Настройку делают один раз на компьютере.

**Вы научитесь:**

- открывать терминал и выполнять в нём команды;
- устанавливать Git и проверять установку;
- настраивать имя, почту и другие параметры Git;
- проверять текущую конфигурацию.

**Время:** 30–45 минут. **Понадобится:** компьютер с Windows 10 или 11 и права на установку программ.

## 2.1. Что такое терминал

> **Терминал** — окно, в котором компьютером управляют текстовыми командами. Вы пишете команду, нажимаете <kbd>Enter</kbd>, компьютер выполняет её и печатает результат.

Пример. Команда `pwd` выводит адрес папки, в которой вы сейчас находитесь:

```powershell
pwd
```

```text
Path
----
C:\Users\Ivan
```

В Windows есть несколько программ-терминалов. Для этой методички подойдут две:

| Программа | Что это | Когда использовать |
| --- | --- | --- |
| **PowerShell** | Стандартная командная оболочка Windows | По умолчанию во всех примерах методички |
| **Git Bash** | Оболочка в стиле Linux, ставится вместе с Git | Если вам привычнее Linux-команды |

> **Оболочка** (*shell*) — программа, которая понимает ваши команды. PowerShell и Git Bash — разные оболочки. Команды Git работают в них одинаково, а команды для работы с файлами немного различаются.

### Как открыть PowerShell

1. Нажмите <kbd>Win</kbd>.
2. Наберите `Терминал` (в Windows 11) или `PowerShell` (в Windows 10).
3. Нажмите <kbd>Enter</kbd>.

Откроется окно со строкой вроде этой:

```text
PS C:\Users\Ivan>
```

Это **приглашение** (*prompt*). `PS` означает PowerShell, дальше — текущая папка. Команду пишут после знака `>`.

> [!IMPORTANT]
> В примерах методички приглашение не показано. Набирайте только саму команду: `git status`, а не `PS C:\Users\Ivan> git status`.

### Как открыть терминал сразу в нужной папке

1. Откройте папку проекта в Проводнике.
2. Щёлкните правой кнопкой мыши по пустому месту в папке.
3. Выберите **Открыть в Терминале**.

В Windows 10 этого пункта может не быть. Тогда откройте PowerShell и перейдите в папку командой `cd` (см. ниже).

### Пять команд, которых хватит для начала

| Команда (PowerShell) | Что делает | Пример |
| --- | --- | --- |
| `pwd` | Показывает текущую папку | `pwd` |
| `ls` | Показывает файлы в текущей папке | `ls` |
| `cd <папка>` | Переходит в папку | `cd Documents` |
| `cd ..` | Поднимается на одну папку вверх | `cd ..` |
| `mkdir <имя>` | Создаёт папку | `mkdir projects` |

Ещё три полезные команды:

- `notepad <файл>` — открыть файл в Блокноте (если файла нет, Блокнот предложит его создать);
- `explorer .` — открыть текущую папку в Проводнике (точка означает «текущая папка»);
- `cls` — очистить экран.

> **Путь** — адрес файла или папки, например `C:\Users\Ivan\projects`. Знак `~` — короткая запись домашней папки пользователя: `~\projects` то же самое, что `C:\Users\Ivan\projects`.

### Приёмы, которые экономят время

- <kbd>Tab</kbd> — дописать имя файла или папки. Наберите `cd Doc` и нажмите <kbd>Tab</kbd>.
- <kbd>↑</kbd> и <kbd>↓</kbd> — листать ранее введённые команды.
- <kbd>Ctrl</kbd>+<kbd>C</kbd> — прервать выполняющуюся команду.
- Вставить текст в терминал: <kbd>Ctrl</kbd>+<kbd>V</kbd> или правая кнопка мыши.

> [!TIP]
> Называйте папки проектов латиницей и без пробелов: `my-site`, а не `Мой сайт`. Так меньше проблем с командами и адресами на GitHub.

## 2.2. Установка Git на Windows

### Способ 1. Установщик с официального сайта (рекомендуется)

1. Откройте страницу [git-scm.com/install/windows](https://git-scm.com/install/windows).
2. Скачайте установщик для вашего компьютера. Почти всегда это **x64**. Для компьютеров на процессоре ARM выберите **ARM64**.
3. Запустите скачанный файл. Windows спросит разрешение на изменения — нажмите **Да**.
4. Проходите страницы мастера кнопкой **Next**. На большинстве страниц оставьте значения по умолчанию. Две страницы стоит изменить — они выделены в таблице.

| Страница установщика | Что выбрать | Почему |
| --- | --- | --- |
| Select Components | По умолчанию | Нужные компоненты уже отмечены |
| **Choosing the default editor used by Git** | **Use Notepad as Git's default editor** (или Visual Studio Code, если он установлен) | По умолчанию стоит Vim — сложный для новичка редактор |
| **Adjusting the name of the initial branch in new repositories** | **Override the default branch name for new repositories**, в поле — `main` | Иначе новые репозитории получат ветку `master`, а GitHub использует `main` |
| Adjusting your PATH environment | Git from the command line and also from 3rd-party software (Recommended) | Git будет доступен в PowerShell |
| Choosing the SSH executable | Use bundled OpenSSH | По умолчанию |
| Choosing HTTPS transport backend | Use the native Windows Secure Channel library | По умолчанию |
| Configuring the line ending conversions | Checkout Windows-style, commit Unix-style line endings | Правильные концы строк для Windows (см. ниже) |
| Configuring the terminal emulator | Use MinTTY | По умолчанию |
| Choose the default behavior of `git pull` | Merge (в установщиках до середины 2026 года — Fast-forward or merge) | По умолчанию |
| Choose a credential helper | Git Credential Manager | Позволяет входить в GitHub через браузер |
| Configuring extra options | По умолчанию | — |

5. Нажмите **Install**, дождитесь окончания и нажмите **Finish**.

> [!NOTE]
> Названия страниц приведены для Git for Windows 2.56 (октябрь 2026). В других версиях формулировки могут немного отличаться. Если сомневаетесь — оставляйте значение по умолчанию: всё важное мы всё равно настроим командами в разделе 2.4.

> **Концы строк.** В Windows строка текста заканчивается двумя невидимыми символами (CRLF), в Linux и macOS — одним (LF). Выбранная настройка хранит в репозитории формат LF, а в рабочей папке показывает файлы в формате Windows. Поэтому вы иногда увидите предупреждение `LF will be replaced by CRLF` — это нормально.

### Способ 2. Через winget

> **winget** — встроенный в Windows 10 и 11 менеджер программ: он устанавливает программы одной командой.

```powershell
winget install --id Git.Git -e --source winget
```

- `--id Git.Git` — какую программу установить;
- `-e` — искать точное совпадение названия;
- `--source winget` — брать программу из официального каталога winget.

Winget ставит Git с настройками по умолчанию: редактор Vim и ветка `master`. Обязательно выполните настройку из раздела 2.4. Новая версия Git может появиться в каталоге winget с задержкой в несколько дней.

## 2.3. Проверка установки

1. **Закройте и снова откройте** терминал. Новое окно узнает об установленной программе.
2. Выполните:

```powershell
git --version
```

Ожидаемый результат (номер версии может быть новее):

```text
git version 2.56.0.windows.2
```

Если вы видите номер версии — Git установлен.

### Если команда не найдена

```text
git : Имя "git" не распознано как имя командлета, функции, файла сценария или выполняемой программы.
```

В англоязычной Windows: `The term 'git' is not recognized...`.

Что сделать:

1. Закройте все окна терминала и откройте новое.
2. Если не помогло — перезагрузите компьютер.
3. Если и это не помогло — запустите установщик ещё раз и на странице **Adjusting your PATH environment** выберите вариант **(Recommended)**.

## 2.4. Первая настройка Git

Git записывает в каждый коммит имя и почту автора. Без них Git откажется сохранять версии. Выполните команды по одной, подставив свои данные.

### Имя

```powershell
git config --global user.name "Иван Петров"
```

- `git config` — команда настройки Git;
- `--global` — настройка для всех ваших репозиториев на этом компьютере;
- `user.name` — имя параметра;
- `"Иван Петров"` — значение. Кавычки нужны, потому что в имени есть пробел.

Команда ничего не выводит. Это нормально: в терминале «тишина» обычно означает успех.

### Почта

```powershell
git config --global user.email "ivan.petrov@example.com"
```

Укажите почту, которую используете (или будете использовать) на GitHub. Тогда GitHub свяжет ваши коммиты с вашим профилем.

> [!IMPORTANT]
> Почта из коммитов видна всем, кто видит репозиторий. Если не хотите показывать настоящий адрес, GitHub даёт специальный скрытый адрес вида `12345678+login@users.noreply.github.com`. Как его получить — в [главе 4](04_rabota_s_github.md#42-настройка-приватности-почты). Почту в настройке можно поменять в любой момент той же командой.

### Имя основной ветки

```powershell
git config --global init.defaultBranch main
```

Новые репозитории будут сразу создаваться с веткой `main` — как на GitHub. Если вы выбрали `main` в установщике, команда просто подтвердит выбор.

### Редактор

```powershell
git config --global core.editor notepad
```

Иногда Git открывает редактор, чтобы вы написали сообщение (например, при слиянии веток). С этой настройкой откроется Блокнот: напишите текст, сохраните (<kbd>Ctrl</kbd>+<kbd>S</kbd>) и **закройте окно** — только тогда Git продолжит работу.

Если у вас установлен Visual Studio Code, можно выбрать его:

```powershell
git config --global core.editor "code --wait"
```

> [!TIP]
> **Если Git всё же открыл Vim** (экран с тильдами `~` слева), выйти можно так: нажмите <kbd>Esc</kbd>, наберите `:wq` и нажмите <kbd>Enter</kbd> — сохранить и выйти. `:q!` — выйти без сохранения.

### Русские имена файлов

```powershell
git config --global core.quotepath false
```

Без этой настройки Git показывает русские имена файлов в виде кодов: `"\320\277\320\273\320\260\320\275.txt"`. С ней — нормально: `план.txt`.

## 2.5. Проверка конфигурации

Посмотрите все глобальные настройки:

```powershell
git config --global --list
```

Ожидаемый результат:

```text
user.name=Иван Петров
user.email=ivan.petrov@example.com
init.defaultbranch=main
core.editor=notepad
core.quotepath=false
```

Git показывает имена параметров маленькими буквами — `init.defaultbranch`. Регистр в именах параметров не важен.

Узнать одно значение:

```powershell
git config user.name
```

```text
Иван Петров
```

Узнать, в каком файле записана каждая настройка:

```powershell
git config --list --show-origin
```

```text
file:C:/Program Files/Git/etc/gitconfig    init.defaultbranch=master
file:C:/Users/Ivan/.gitconfig              user.name=Иван Петров
file:C:/Users/Ivan/.gitconfig              init.defaultbranch=main
...
```

Настройки хранятся на трёх уровнях. Более близкий уровень важнее:

| Уровень | Флаг | Файл | Действует |
| --- | --- | --- | --- |
| Системный | `--system` | `C:\Program Files\Git\etc\gitconfig` | Для всех пользователей компьютера |
| Глобальный | `--global` | `C:\Users\<вы>\.gitconfig` | Для всех ваших репозиториев |
| Локальный | `--local` | `.git\config` внутри проекта | Только для одного репозитория |

В примере выше системный файл говорит `master`, а глобальный — `main`. Побеждает глобальный, поэтому новые репозитории получат ветку `main`.

> [!NOTE]
> В Git 2.46 появилась новая запись команд: `git config list`, `git config get user.name`, `git config set --global user.name "..."`. Старая запись, которую использует методичка, тоже работает. Документация рекомендует со временем переходить на новую.

## 2.6. PowerShell и Git Bash: что выбрать

Команды Git одинаковы в обеих оболочках. Различаются команды для работы с файлами и запись путей.

| Действие | PowerShell | Git Bash |
| --- | --- | --- |
| Показать текущую папку | `pwd` | `pwd` |
| Показать файлы, включая скрытые | `ls -Force` | `ls -a` |
| Путь к папке | `C:\Users\Ivan\projects` | `/c/Users/Ivan/projects` |
| Показать содержимое файла | `cat file.txt` | `cat file.txt` |
| Удалить папку со всем содержимым | `Remove-Item -Recurse folder` | `rm -r folder` |
| Создать пустой файл | `New-Item file.txt` | `touch file.txt` |

Рекомендация: начните с PowerShell — все примеры методички написаны для него. Git Bash пригодится, когда вы встретите в интернете инструкции для Linux или macOS.

Чтобы открыть Git Bash: <kbd>Win</kbd> → наберите `Git Bash` → <kbd>Enter</kbd>.

> [!WARNING]
> Команды удаления (`Remove-Item -Recurse`, `rm -r`) удаляют файлы **мимо Корзины**. Восстановить их обычно нельзя. Перед запуском проверьте, в какой папке вы находитесь (`pwd`).

## Проверьте себя

1. Откройте PowerShell и выполните `git --version`. Что вы видите?
2. Выполните `git config --global --list`. Есть ли в списке `user.name`, `user.email` и `init.defaultbranch=main`?
3. Создайте папку `projects` в домашней папке и перейдите в неё.

<details>
<summary>Ожидаемый результат</summary>

1. Строка вида `git version 2.56.0.windows.2`.
2. Да, все три параметра с вашими значениями.
3. Команды:

   ```powershell
   cd ~
   mkdir projects
   cd projects
   pwd
   ```

   `pwd` покажет `C:\Users\<ваше имя>\projects`.

</details>
