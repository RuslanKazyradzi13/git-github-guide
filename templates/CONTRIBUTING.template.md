# Как участвовать в проекте [НАЗВАНИЕ ПРОЕКТА]

Спасибо, что хотите помочь! Здесь описано, как предложить изменение так, чтобы его было легко принять.

## Перед началом

- Ошибку или идею сначала обсудите в [Issue](https://github.com/[ВЛАДЕЛЕЦ]/[РЕПОЗИТОРИЙ]/issues): возможно, над ней уже работают.
- Небольшие исправления (опечатки, документация) можно присылать сразу Pull Request.
- Об уязвимостях сообщайте не в Issue, а по правилам [SECURITY.md](SECURITY.md).
<!-- По ситуации: если в проекте есть кодекс поведения. -->
- Участвуя в проекте, вы соглашаетесь соблюдать [кодекс поведения](CODE_OF_CONDUCT.md).

## Как внести изменение

1. Создайте ветку от `main`: `git switch -c [ТИП]/[КРАТКОЕ-ОПИСАНИЕ]`, например `fix/menu-typo`.
2. Внесите изменения. Новое поведение сопровождайте тестами.
3. Запустите проверки:

   ```powershell
   [КОМАНДА ЛИНТЕРА]
   [КОМАНДА ТЕСТОВ]
   ```

4. Обновите документацию (README) и раздел `[Unreleased]` в `CHANGELOG.md`, если изменение заметно пользователям.
5. Сделайте коммит. <!-- Выберите формат сообщений; например, Conventional Commits. --> Формат сообщений: [ФОРМАТ, например Conventional Commits: `fix: ...`, `feat: ...`, `docs: ...`].
6. Отправьте ветку и откройте Pull Request. Заполните шаблон описания.

## Ревью и слияние

<!-- Кто смотрит изменения, какие проверки обязательны, сколько обычно ждать ответа. -->
Pull Request сливается, когда:

- все автоматические проверки прошли;
- изменения одобрил [КТО: сопровождающий проекта / один из CODEOWNERS].

Обычно ответ занимает [СРОК]. Если ответа долго нет — напомните о себе в комментарии.
