# Чек-лист готовности репозитория к публикации

Пройдите чек-лист перед тем, как сделать репозиторий публичным или выпустить версию. Уровни накопительные: профессиональный уровень включает базовый, open-source — оба предыдущих.

Как отмечать:

- `[x]` — выполнено;
- `[ ]` — не выполнено;
- если пункт осознанно пропущен — оставьте `[ ]` и допишите причину: `— не нужно: нет зависимостей`.

Подробности — в главах [9](../09_standarty_i_oformlenie_proektov.md), [10](../10_litsenzii_i_avtorskie_prava.md) и [11](../11_bezopasnost_i_avtomatizatsiya.md).

Проект: **[НАЗВАНИЕ]** · Версия: **[X.Y.Z]** · Дата проверки: **[ГГГГ-ММ-ДД]** · Проверил: **[ИМЯ]**

## Уровень 1. Базовый — небольшой личный проект

### Содержимое

- [ ] `README.md`: что это, как установить, как запустить.
- [ ] Команды из README работают, если их скопировать.
- [ ] `.gitignore` подходит языку и инструментам проекта.
- [ ] В репозитории нет временных и служебных файлов (`__pycache__`, `node_modules`, `.DS_Store`, логи).
- [ ] Нет больших двоичных файлов без необходимости (файлы больше 100 МБ GitHub не принимает).

### Безопасность

- [ ] В коде **и в истории** нет паролей, токенов, ключей, личных данных (`git log -p`, поиск по словам `password`, `token`, `secret`, `key`).
- [ ] Файл `.env` в `.gitignore`; при наличии настроек есть `.env.example`.
- [ ] В аккаунте GitHub включена двухфакторная аутентификация.

### Права и лицензия

- [ ] Вы имеете право публиковать весь код (нет кода работодателя или заказчика без разрешения).
- [ ] Для публичного кода выбрана лицензия и добавлен файл `LICENSE` с годом и правообладателем, если требуется.

### История

- [ ] Сообщения коммитов понятны.
- [ ] `git status` чистый, всё отправлено на GitHub.

## Уровень 2. Профессиональный — документация, тесты, качество, сопровождение

### Документация

- [ ] README содержит требования, настройку, тестирование, статус и ограничения.
- [ ] `CHANGELOG.md` по Keep a Changelog; раздел версии заполнен.
- [ ] `CONTRIBUTING.md` описывает подготовку окружения, проверки и порядок Pull Request.
- [ ] Архитектура и важные решения описаны в `docs/` (если проект не тривиальный).

### Качество

- [ ] Есть автоматические тесты; они проходят.
- [ ] Линтер и (по желанию) форматтер настроены, версии закреплены.
- [ ] Workflow CI запускается в каждом Pull Request и при push в `main`.
- [ ] `.editorconfig` и `.gitattributes` добавлены.

### Процесс

- [ ] Ветка `main` защищена: запрещены удаление и force push; обязательны Pull Request и успешные проверки.
- [ ] Шаблон Pull Request с чек-листом (для командной работы).
- [ ] Версия соответствует Semantic Versioning; поставлен аннотированный тег `vX.Y.Z`.
- [ ] Релиз на GitHub с заметками о выпуске.

### Безопасность

- [ ] `SECURITY.md` с реальным закрытым каналом связи.
- [ ] Dependabot alerts включены; `.github/dependabot.yml` настроен.
- [ ] В workflow указано `permissions: contents: read`; сторонние действия закреплены полным хешем коммита.
- [ ] Секреты CI хранятся в **Settings** → **Secrets and variables**, а не в файлах.
- [ ] Лицензии зависимостей проверены и совместимы с лицензией проекта.

## Уровень 3. Публичный open-source — сообщество, безопасность, лицензирование, релизы

### Сообщество

- [ ] `CODE_OF_CONDUCT.md` с реальным контактом для жалоб и человеком, который их рассматривает.
- [ ] Шаблоны Issue (`.github/ISSUE_TEMPLATE/`) и `config.yml`.
- [ ] В `CONTRIBUTING.md` указаны условия приёма вклада (лицензия проекта, DCO или CLA).
- [ ] Описание и темы (*topics*) репозитория заполнены.

### Безопасность

- [ ] Включены закрытые сообщения об уязвимостях (Private vulnerability reporting).
- [ ] Secret scanning и push protection включены.
- [ ] CodeQL (default setup) включён, если язык поддерживается.
- [ ] Dependency review в Pull Request (где доступен).
- [ ] Проверена оценка OpenSSF Scorecard; критичные замечания исправлены или осознанно приняты.
- [ ] У сопровождающих включена 2FA; доступ есть только у тех, кому он нужен.

### Лицензирование

- [ ] SPDX-идентификатор лицензии в манифесте пакета.
- [ ] `THIRD_PARTY_NOTICES.md` или `NOTICE` для встроенных сторонних компонентов.
- [ ] По желанию — сведения о лицензии в каждом файле, проверка `reuse lint`.
- [ ] Для научного ПО — `CITATION.cff`.

### Релизы

- [ ] Релизы собираются в CI, а не на личном компьютере.
- [ ] Заметки о выпуске перечисляют несовместимые изменения и исправления безопасности.
- [ ] По желанию — аттестации происхождения сборки (SLSA, GitHub Artifact Attestations).
- [ ] Указано, какие версии поддерживаются (`SECURITY.md`).
