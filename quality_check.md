## Что исправлено по итогам проверки

- Учебный проект: значение точности по умолчанию изменено на 2 знака, чтобы примеры в README не зависели от округления чисел с плавающей точкой.
- Схемы: устранены наложения подписей на стрелки и переполнение текста в карточках; пути в схеме структуры репозитория отрисовываются с отступами.
- Шаблоны: служебные комментарии не содержат вложенных `-->`, которые обрывали комментарий.
- Глава 11: шаги создания правил ветки приведены к текущей документации GitHub (названия правил, статус применения).
- Глава 6, глава 7: у двух упоминаний опасных команд добавлены явные предупреждения.
- Глава 9: заголовок главы отделён от названия части II.
- Все файлы приведены к единому формату концов строк (LF).

### Независимая вычитка

Все главы, шаблоны и пример вычитал отдельный проверяющий: искал ошибки в командах, противоречия, нарушенный порядок шагов, опасные команды без предупреждений, неопределённые термины, неточности в юридических формулировках и языковые ошибки. Найдено 8 ошибок, 9 противоречий и 26 предложений по улучшению. Исправлено:

**Ошибки**

- Глава 4, сценарий А: до первого коммита `git restore --staged` завершается ошибкой `fatal: could not resolve 'HEAD'` (проверено) — заменено на `git rm --cached <файл>`; то же пояснение добавлено в раздел 6.4.
- Глава 8, проект 2: после каждого коммита добавлен `git push`, поэтому `git pull` после создания `LICENSE` на сайте выполняется перемоткой без коммита слияния; указание про `license = "MIT"` заменено проверкой и командами коммита.
- Глава 4: после установки GitHub CLI добавлен перезапуск терминала; вход по токену описан через окно Git Credential Manager и с нужным правом **Contents: Read and write**; дополнен ожидаемый вывод `git status` после `git rm`.
- Глава 6: совет перед публикацией приведён в соответствие с моментом проверки (`git diff --staged` — перед коммитом, `git log --stat` — перед push).
- Пример `tempconv`: запуск без установки показан с синтаксисом переменных PowerShell.

**Противоречия**

- `git push --force-with-lease` в главе 6 больше не связывается с очисткой секрета: для неё действует процедура раздела 11.8.
- Уровни зрелости согласованы во всех местах (глава 9, обе схемы, глава 8, чек-лист): `SECURITY.md`, шаблон Pull Request (в команде) и проверка лицензий зависимостей — профессиональный уровень.
- Порядок изучения: проект 2 главы 8 выполняется после глав 9–11 (README, глава 8, глава 9).
- Учебный проект 2 начинается с версии 0.1.0 — совпадает с тегом `v0.1.0`.
- Термины: CLA «предоставляет права» (а не «передаёт»); участник репозитория GitHub (*collaborator*) отделён от соавтора в смысле авторского права.
- Пример сообщения коммита: Python 3.15 вместо уже включённой 3.14.
- README: для сборки PDF указан Python с PyMuPDF; обозначения заполнителей описаны единообразно (`<логин>` в командах, `[ЗАПОЛНИТЕЛЬ]` в шаблонах, `OWNER` в учебном проекте).

**Улучшения**

- `git restore .` описан точно: удаляет неподготовленные правки; для полного сброса — `git restore --staged --worktree .` (проверено).
- Пример dependency review переведён на `allow-licenses`: параметр `deny-licenses` в действии версии 5 объявлен устаревшим (проверено по README действия).
- Уточнены формулировки о патентных положениях лицензий, совместимости («как правило») и позиции FSF о JavaScript.
- Добавлены: установка git filter-repo, поиск секретов в истории `git log -p -i -G "password|token|secret|key"` (проверено), `git fetch --prune` после удаления ветки на сайте, оговорка про коммит слияния в варианте А, определения хуков и тега, термины `origin/main`, rebase и worktree в словаре; восстановлен алфавитный порядок словаря.
- Таблица режимов `git reset`, создание `.gitignore`, подсказка о `Set-ExecutionPolicy` в `CONTRIBUTING.md` примера, флаги winget, ссылки на разделы.
- Проверено и оставлено без изменений: черновые Pull Request в текущей документации GitHub не ограничены тарифом.

## Известные ограничения

- **Схемы интерфейса GitHub — не снимки экрана.** Они нарисованы по документации GitHub и помечены как схематические. Интерфейс GitHub регулярно меняется.
- **Некоторые подписи интерфейса не удалось проверить без входа в аккаунт:** точные надписи переключателей в форме нового репозитория (README, .gitignore, лицензия), надписи окна Git Credential Manager, кнопка **History** у файла, точный текст сообщений GH007 и GH013. В методичке они приведены в общепринятом виде и сопровождаются описанием действия.
- **Вывод команд получен в Git 2.55**, а актуальная версия — 2.56. Формулировки сообщений могут незначительно отличаться. Git для Windows выводит сообщения на английском; русский перевод дан в тексте.
- **gnu.org был недоступен из сети проверки** (тайм-аут соединения). Ссылки на тексты GNU — канонические адреса; содержание сверялось по официальным страницам до потери соединения и по их архивной копии.
- **Тексты стандартов ISO платные.** Перечни характеристик ISO/IEC 25010 и ISO/IEC/IEEE 29148 и структура процессов ISO/IEC/IEEE 12207 даны по общедоступным описаниям на iso.org и вторичным источникам. Группы процессов приведены по редакции 2017 года с оговоркой.
- **Юридические сведения — образовательные.** Они не заменяют консультацию юриста; правила зависят от страны, договоров и лицензий компонентов. Примеры по праву РФ, ЕС, Германии и США приведены как иллюстрации и не являются исчерпывающими.
- **Сведения о тарифах и доступности функций GitHub** (минуты Actions, rulesets, secret scanning, CodeQL) актуальны на дату проверки и могут измениться.
- **Claude Code развивается быстро.** Режимы разрешений, команды и пути настроек проверены по документации на дату проверки.
- **Ориентация на Windows.** Команды даны для PowerShell; для Linux и macOS отличаются команды работы с файлами и установка.
- **Mermaid на GitHub** может отображать диаграммы немного иначе, чем в PDF: используется другая версия библиотеки и тема оформления.
- **Учебный workflow не запускался на GitHub** в рамках проверки: он проверен локально (те же команды, линтер, тесты, корректность YAML и хешей действий).
- **Лицензирование методички** выбрано правообладателем при публикации: тексты, схемы и шаблоны — CC BY 4.0, код — MIT (см. README). Для шаблонов это означает, что при их копировании нужно указывать авторство.

## Как повторить проверку

```powershell
python tools/toc.py
python tools/check_links.py --web
cd examples\tempconv
python -m pip install -e . -r requirements-dev.txt
ruff check .
python -m unittest discover -s tests -v
cd ..\..
node tools/build_pdf.mjs
```
