# Словарь терминов

Термины методички в алфавитном порядке: сначала названия на латинице, затем на кириллице. В скобках — английский вариант и глава, где термин разобран подробно.

## Термины на латинице

**.editorconfig** — файл с правилами форматирования (отступы, кодировка, концы строк), которые редакторы применяют автоматически. *Пример:* `indent_size = 4`. Глава 9.

**.env** — файл с настоящими значениями настроек и секретов для локального запуска. В Git не добавляется. Глава 11.

**.env.example** — образец файла `.env` без секретов: имена переменных и безопасные значения. Хранится в Git. Глава 11.

**.gitattributes** — файл с правилами для Git: какие файлы текстовые, какие двоичные, какие концы строк хранить. *Пример:* `* text=auto`. Глава 9.

**.gitignore** — список файлов и папок, которые Git должен игнорировать. *Пример:* строка `.env`. Глава 6.

**ADR** (*Architecture Decision Record*) — запись архитектурного решения: контекст, решение, последствия. Хранятся в `docs/adr/`. Глава 7.

**AGPL** (*GNU Affero General Public License*) — copyleft-лицензия, которая дополнительно требует предлагать исходный код изменённой программы пользователям, работающим с ней по сети. Глава 10.

**Apache-2.0** — разрешительная лицензия с явной патентной лицензией и правилами о файле `NOTICE`. Глава 10.

**API** (*Application Programming Interface*) — способ, которым одна программа обращается к другой. *Пример:* программа запрашивает погоду у сервиса через его API. Глава 6.

**ASVS** (*Application Security Verification Standard*) — стандарт OWASP с проверяемыми требованиями к безопасности приложений. Глава 9.

**BSD-2-Clause, BSD-3-Clause** — короткие разрешительные лицензии; BSD-3 дополнительно запрещает использовать имена авторов в рекламе без разрешения. Глава 10.

**CHANGELOG** — журнал изменений проекта по версиям для пользователей. Глава 9.

**CI** (*continuous integration*, непрерывная интеграция) — автоматическая проверка каждого изменения: сборка, тесты, линтер. Глава 11.

**CI/CD** — непрерывная интеграция и непрерывная доставка: автоматические проверки и автоматическая выкладка версии. Глава 11.

**CITATION.cff** — файл с правилами цитирования программы в научных работах. Глава 10.

**CLA** (*Contributor License Agreement*) — соглашение, по которому участник предоставляет проекту права на свой вклад (обычно в виде лицензии). Глава 10.

**Claude Code** — AI-ассистент для программирования от Anthropic: работает с файлами проекта, запускает команды и тесты. Глава 7.

**CLAUDE.md** — файл с инструкциями для Claude Code: команды, правила проекта. Глава 7.

**CODE_OF_CONDUCT.md** — кодекс поведения участников проекта. Глава 9.

**CODEOWNERS** — файл, который назначает ответственных ревьюеров для частей репозитория. Глава 11.

**CodeQL** — анализатор GitHub, который ищет уязвимости в исходном коде. Глава 11.

**CONTRIBUTING.md** — правила участия в проекте. Глава 9.

**Conventional Commits** — соглашение о формате сообщений коммитов: `feat: ...`, `fix: ...`. Глава 9.

**Copyleft** (копилефт) — условие лицензии: изменённые версии при распространении должны выходить на тех же условиях и с исходным кодом. Глава 10.

**CRLF, LF** — невидимые символы конца строки: CRLF принят в Windows, LF — в Linux и macOS. Глава 2.

**DCO** (*Developer Certificate of Origin*) — заявление участника, что он вправе отправить код; подтверждается командой `git commit -s`. Глава 10.

**Dependabot** — функция GitHub, которая предупреждает об уязвимых зависимостях и предлагает обновления. Глава 11.

**Detached HEAD** («отсоединённый HEAD») — состояние, когда вы находитесь на конкретном коммите, а не на ветке. Глава 6.

**diff** — построчная разница между двумя версиями файла. *Пример:* `git diff`. Глава 3.

**Fast-forward** («перемотка вперёд») — слияние без нового коммита: ветка просто передвигается вперёд. Глава 5.

**fetch** — скачать новые коммиты с удалённого репозитория, не меняя свои файлы. Глава 3.

**Fork** (форк) — копия чужого репозитория в вашем аккаунте GitHub. Глава 5.

**Git** — бесплатная программа для контроля версий. Глава 1.

**Git Bash** — оболочка в стиле Linux, которая устанавливается вместе с Git для Windows. Глава 2.

**Git Credential Manager** (GCM) — программа для безопасного хранения данных входа; позволяет входить в GitHub через браузер. Глава 4.

**GitHub** — сайт и облачный сервис для хранения Git-репозиториев и совместной работы. Глава 1.

**GitHub Actions** — система автоматизации GitHub: запускает workflow по событиям. Глава 11.

**GitHub CLI** (`gh`) — официальная программа GitHub для работы из терминала. Глава 4.

**GitHub Flow** — рабочий процесс: ветка → коммиты → Pull Request → ревью → слияние → удаление ветки. Глава 5.

**GPL** (*GNU General Public License*) — copyleft-лицензия: распространяемая производная программа должна быть под GPL с исходным кодом. Глава 10.

**HEAD** — указатель «вы находитесь здесь»: обычно последний коммит текущей ветки. Глава 3.

**Issue** — задача, сообщение об ошибке или идея в репозитории GitHub. Глава 1.

**Keep a Changelog** — рекомендации по ведению журнала изменений. Глава 9.

**LGPL** (*GNU Lesser General Public License*) — слабый copyleft для библиотек. Глава 10.

**LICENSE** — файл с текстом лицензии проекта. Глава 10.

**main** — основная ветка репозитория со стабильной версией. В старых проектах — `master`. Глава 5.

**Markdown** — простой язык разметки текста. Файлы с расширением `.md`. Глава 4.

**merge** (слияние) — объединение изменений из одной ветки в другую. Глава 5.

**Mermaid** — язык для описания диаграмм текстом; GitHub показывает такие диаграммы в Markdown. Глава 9.

**MIT** — короткая разрешительная лицензия. Глава 10.

**MPL-2.0** (*Mozilla Public License*) — слабый copyleft на уровне файлов. Глава 10.

**NOTICE** — файл с обязательными атрибуциями по лицензии Apache-2.0. Глава 10.

**OpenSSF Scorecard** — инструмент автоматической оценки практик безопасности open-source-проектов. Глава 9.

**origin** — стандартное имя главного удалённого репозитория. Глава 4.

**origin/main** — локальная «закладка», которая помнит, где была ветка `main` на GitHub при последней синхронизации (`fetch`, `pull`, `push`). Глава 4.

**OWASP** — открытое сообщество по безопасности приложений; автор ASVS, SAMM и Top 10. Глава 9.

**PAT** (*personal access token*) — персональный токен доступа вместо пароля для команд Git и API. Глава 4.

**PowerShell** — стандартная командная оболочка Windows. Глава 2.

**Provenance** (происхождение) — проверяемые сведения о том, кто, из чего и как собрал файл. Глава 9.

**pull** — скачать и сразу применить изменения с удалённого репозитория (`fetch` + `merge`). Глава 3.

**Pull Request** (PR) — запрос на слияние изменений из одной ветки в другую с обсуждением и проверкой. Глава 5.

**push** — отправить коммиты в удалённый репозиторий. Глава 3.

**Push protection** — проверка GitHub, которая блокирует push с секретами. Глава 11.

**README.md** — главная страница проекта. Глава 4 и 9.

**rebase** — способ перенести коммиты ветки на новое основание, переписывая их; альтернатива слиянию. В методичке не используется: для начала достаточно `merge`. Глава 5.

**reflog** — локальный журнал перемещений `HEAD`; помогает найти «потерянные» коммиты. Глава 6.

**Release** (релиз) — страница выпуска версии на GitHub, связанная с тегом. Глава 9.

**remote** — удалённый репозиторий. Глава 4.

**REUSE** — практика указывать лицензию и правообладателя для каждого файла. Глава 9 и 10.

**Rulesets** — правила для веток и тегов на GitHub: например, запрет force push и обязательный PR. Глава 11.

**SAMM** (*Software Assurance Maturity Model*) — модель зрелости практик безопасной разработки OWASP. Глава 9.

**SBOM** (*Software Bill of Materials*) — список компонентов программы с версиями и лицензиями. Глава 9.

**Secret scanning** — автоматический поиск секретов в репозитории. Глава 11.

**SemVer** (*Semantic Versioning*) — правила номеров версий `MAJOR.MINOR.PATCH`. Глава 9.

**SLSA** — спецификация уровней защиты цепочки сборки ПО. Глава 9.

**SPDX** — стандарт сведений о лицензиях и составе ПО; даёт идентификаторы лицензий вроде `MIT`. Глава 9 и 10.

**SSH-ключ** — пара ключей для входа на сервер без пароля; публичную часть добавляют на GitHub. Глава 4.

**Staging area** (индекс, область подготовки) — изменения, отобранные для следующего коммита. Глава 3.

**stash** — временное хранилище незакоммиченных изменений. Глава 6.

**Tag** (тег) — постоянная метка на коммите, обычно номер версии. *Пример:* `v1.0.0`. Глава 9.

**Unlicense** — попытка передать код в общественное достояние с запасной разрешительной лицензией. Глава 10.

**upstream** — связанная ветка на удалённом репозитории, с которой работают `git pull` и `git push` без параметров. Глава 4.

**winget** — менеджер программ Windows. Глава 2.

**Workflow** — сценарий автоматизации GitHub Actions в файле `.github/workflows/*.yml`. Глава 11.

**Worktree** (рабочее дерево) — дополнительная папка с другой веткой того же репозитория; позволяет работать над несколькими ветками одновременно. Глава 7.

**YAML** — текстовый формат настроек, где вложенность задаётся отступами. Глава 11.

## Термины на кириллице

**Авторское право** (*copyright*) — права автора на произведение; для программ возникают автоматически при создании. Глава 10.

**Аннотированный тег** — тег с автором, датой и сообщением; используется для релизов (`git tag -a`). Глава 9.

**Архитектура** — устройство программы: из каких частей она состоит и как они связаны. Глава 7.

**Ветка** (*branch*) — независимая линия разработки. Глава 1 и 5.

**Двухфакторная аутентификация** (2FA) — вход с паролем и вторым подтверждением (код из приложения, ключ). Глава 4.

**Зависимость** (*dependency*) — чужая библиотека, которую использует проект. Глава 7 и 10.

**История изменений** — цепочка коммитов от первого до последнего. Глава 1.

**Клонирование** (*clone*) — скачивание репозитория со всей историей. Глава 3.

**Коммит** (*commit*) — сохранённый снимок проекта с автором, датой и сообщением. Глава 1 и 3.

**Контрольная точка** — сохранённое состояние, к которому можно вернуться: коммит, ветка или тег. Глава 7.

**Конфликт слияния** (*merge conflict*) — ситуация, когда обе ветки по-разному изменили одно место файла, и Git просит выбрать вариант вручную. Глава 6.

**Линтер** (*linter*) — программа, которая ищет ошибки и подозрительные места в коде без запуска. Глава 11.

**Лицензия** — разрешение правообладателя использовать программу на определённых условиях. Глава 10.

**Локальный репозиторий** — репозиторий на вашем компьютере. Глава 1.

**Неотслеживаемый файл** (*untracked*) — файл, за которым Git ещё не следит. Глава 3.

**Оболочка** (*shell*) — программа, которая понимает команды в терминале: PowerShell, Git Bash. Глава 2.

**Ответственное раскрытие** — порядок, при котором об уязвимости сначала сообщают разработчикам закрыто, а публикуют после исправления. Глава 9.

**Патент** — исключительное право на изобретение, например на способ обработки данных. Глава 10.

**Переменная окружения** — именованное значение, которое система передаёт программе при запуске. Глава 11.

**Правообладатель** — тот, кому принадлежат исключительные права на произведение. Глава 10.

**Приглашение** (*prompt*) — строка в терминале перед местом ввода команды, например `PS C:\Users\Ivan>`. Глава 2.

**Принцип минимальных привилегий** — давать людям, программам и токенам только необходимые права. Глава 11.

**Публичный интерфейс** (*public API*) — то, на что опираются пользователи программы: команды, функции, форматы. Глава 9.

**Путь** — адрес файла или папки, например `C:\Users\Ivan\projects`. Глава 2.

**Рабочая папка** (*working directory*) — папка с файлами проекта, которые вы редактируете. Глава 3.

**Разрешительная лицензия** (*permissive*) — лицензия с минимумом условий: MIT, BSD, Apache-2.0. Глава 10.

**Раннер** (*runner*) — виртуальная машина, на которой GitHub Actions выполняет задания. Глава 11.

**Ревью кода** (*code review*) — чтение изменений другим человеком перед их принятием. Глава 5.

**Репозиторий** (*repository*) — папка проекта, за которой следит Git, вместе с историей. Глава 1.

**Секрет** — данные, дающие доступ: пароли, ключи API, токены. Глава 6 и 11.

**Система контроля версий** (СКВ, *version control system*) — программа, которая запоминает изменения файлов и позволяет вернуться к любой версии. Глава 1.

**Слияние** (*merge*) — см. merge.

**Совместимость лицензий** — возможность объединить код под разными лицензиями и распространять результат, соблюдая их все. Глава 10.

**Терминал** — окно для управления компьютером текстовыми командами. Глава 2.

**Тест** — программа, которая проверяет, что код работает как задумано. Глава 7 и 11.

**Удалённый репозиторий** (*remote*) — копия репозитория на сервере, например на GitHub. Глава 4.

**Уязвимость** — ошибка, позволяющая нарушить безопасность программы. Глава 9 и 11.

**Форматтер** (*formatter*) — программа, которая автоматически приводит код к единому оформлению. Глава 11.

**Хеш** (*hash*) — уникальный код коммита из цифр и букв, например `3f2a9c1`. Глава 1.
